# CPU и ожидание под GIL

Тесты из корня репозитория:

```bash
pytest tasks/gil-cpu-vs-wait
```

Прогон из корня репозитория:

```bash
python tasks/gil-cpu-vs-wait/gil_compare.py
```

Скрипт вызывает `compare` дважды: `kind="cpu"` при `iterations=100_000` и `kind="wait"` при `delay=0.05`. Остальные параметры общие: `jobs=4`, `workers=2`, `repeats=3`. `sleep` здесь только модель блокирующего ожидания, не сетевой запрос.

## Наблюдения

Прогон на обычном CPython 3.14.6 с включённым GIL (`gil_enabled=True`).

| Нагрузка | Прогон | sequential, среднее | threads, среднее |
| --- | --- | --- | --- |
| CPU | 1 | 0.023 с | 0.023 с |
| CPU | 2 | 0.026 с | 0.022 с |
| wait | 1 | 0.217 с | 0.110 с |
| wait | 2 | 0.216 с | 0.108 с |

Результаты обоих режимов совпали: для CPU это `4800196…4800199`, для ожидания — `[0, 1, 2, 3]`.

Заметный прирост можно увидеть только на ожидающих тасках, тк для CPU-bound расчеты не выполняются параллельно при использовании пула потоков.
